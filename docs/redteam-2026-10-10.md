# Gray fleet red team — 2026-10-10

Scope: host gray (`~/gray` this repo), graysite's plugin registry (`~/graysite/services/registry`),
grayplugins surface (discord-plugin, telegram, slack, ssh, credpool, sandbox, guard,
permissions), the graydiscordbot support bot, and the update/install chain. Static
code review only; no live exploitation.

## Host gray (this repo)

### High

**H1. Gateway control socket `identify`/`status` ship the daemon's full argv, which
includes the current turn's `-p <prompt>` text.** `gateway/socket.rs:51`. Any process
able to connect to the 0600 unix socket (same-user, or same-box after a privesc) reads
every in-flight prompt, including pasted secrets. Repro:
`printf '{"verb":"identify","id":1}\n' | nc -U ~/.gray/gateway.sock`. Fix: drop `argv`
from the payloads or truncate before `-p`.

**H2. Untrusted per-project prompt templates + AGENTS.md = prompt injection with shell
execution, no consent surface.** `prompt_templates.rs` loads `.claude/commands`,
`.gray/prompts`, `.pi/prompts` from the project directory; skills load from project
paths too. Everything the model does runs unsandboxed (documented in SECURITY.md), so
a cloned repo containing a hostile template or SKILL.md gets one slash-command or
model trigger away from exfiltrating `~/.gray/auth.json`. Repro: `git clone` a repo
with `.claude/commands/review.md`, open gray, run `/review`. Fix: mark project
templates untrusted in the system prompt, or require per-project opt-in.

**H3. Unsigned self-update.** `update.rs` stable-channel `gray update` shells out to
`curl -fsSL https://gray.alignment.id/install.sh | sh`. `GRAY_INSTALLER_SHA256` is an
opt-in pin, and the SHA256SUMS are integrity-only (documented). One compromised origin
(and `gray.alignment.id` sits on the same box that the site deploys to) = full RCE on
every auto-updating install, including cron/gateway ones with no eyes on the output.

### Medium

**M1. Model-created cron jobs are a restart-surviving persistence primitive.**
`gray cron add --script /tmp/runme.sh` needs only absolute-path + is-file validation
(`cron/store.rs`). The model can create jobs from inside a turn. Category: compounding
the always-on threat model; recommend an approval gate for jobs created by the model
itself.

**M2. Gateway pid lock file + umask** — `gateway/pid.rs` creates `gateway.pid.lock`
with `OpenOptions::create(true)` and no explicit mode; umask-dependent. Same finding
class for socket client checks (`unix_query_within` does `path.exists()` then
`connect`, no `lstat` to confirm the target is a socket in user-owned dir).

**M3. `identify`/`status` argv + `logs_tail` — see H1; the `logs_tail` verb also
streams the last 200 lines of `gray.log` over the socket, which is scrubbed but not
necessarily safe to publish to anything that can reach the socket.

### Low / hygiene

- **L1.** `feedback.rs` builds a GitHub prefilled issue URL with raw user text (model
  may have echoed secrets). Run `cron_fire::redact_secrets` over the body before URL
  building.
- **L2.** `plugin check` boots the plugin's `tool/call` without consent hash. Checking
  untrusted code runs it — worth a SECURITY.md note.
- **L3.** `gateway/brain.rs` re-admission after restart increments `attempt` per
  gateway restart, so 3 flaky restarts drops real user events to "abandoned" instead
  of retrying once the gateway is stable again.
- **L4.** `windows_process` alive-check treats `GetExitCodeProcess` failure as alive,
  so stale pid files on Windows never clean up.

## graysite — plugin registry (`~/graysite/services/registry`)

Reviewed: server.mjs, lib/{app,auth,config,http,index-json,publish,rate-limit,
tarball}.mjs, routes/{auth,plugins,usage,waitlist,backers}.mjs. Node http server on
loopback by default; SQLite (node:sqlite); deploy pushes static index.json to the
oracle host.

### Verified solid

- **SSRF egress control is textbook:** `tarball.mjs` resolves every DNS answer, classifies
  each as public/loopback/blocked, rejects private ranges, pins validated answers into the
  socket's own `lookup` option (no TOCTOU between check and dial), follows redirects
  manually with per-hop re-validation, 64 MiB streamed hasher cap. IPv4-in-v6 is
  classified correctly, including 6to4/Teredo xored format and NAT64.
- **Auth:** enrollment codes are 24-byte random, 300s TTL, single-use. API tokens are
  stored SHA-256 only, with a migration that re-keys legacy plaintext rows on first
  successful use — a db leak yields unusable hashes. Verified badge writes restricted
  to maintainer set from env.
- **CORS:** public GETs get `*`; anything with auth/non-GET only gets ACAO reflected
  for the console origin. Good.
- **Art serving:** uploads are base64+magic-sniffed against an allowlist (no SVG), served
  with `nosniff` + null CSP + ETag. Nice.
- **Webhook (backers/Polar):** Standard Webhooks HMAC over raw body, timestamp
  tolerance, `timingSafeEqual`. Correct.
- **Publish validation:** name/version/commands/license regexes, source URL must be an
  https release asset under the claimed repo path on a public forge, repo page probed
  with pinned DNS too.

### Findings

**S1 (Medium). Usage-report endpoint trusts client-supplied cost.** `routes/usage.mjs`
`POST /api/usage/events` accepts `cost_usd` from the CLI and writes ledger rows that
reduce the user's credit balance. A *user* reporting false spend makes their own
balance negative — a nuisance for them, but if any future feature pays out credits
based on ledger rows (the endpoint already has kind 'topup'/'subscription') the same
endpoint is a free-money oracle. Fix: server-side pricing or a share/agent token
scoped to reporting, not to user identity. Also no rate limit on this route (up to 100
events/request, each with arbitrary model string) — cheap DB growth via authenticated
self-DoS.

**S2 (Medium). `syncIndexToOracleNew` shells out with interpolated host/path from env.**
`lib/index-json.mjs` runs `scp ${tempFile} ${config.oracleNewHost}:${config.oracleNewDest}`
via `exec` (shell interp). These are operator-set env vars, not user input — but any
malformed value (or traffic injection into them) is remote code exec on the registry
box. Use `scp -o` variants / `child_process.execFile` / an arg array.

**S3 (Low). Index published from SQLite + `console.error` paths during submit can leak
the base_url userinfo on redirect? (Checked: `source_url` origin-only logging — no
leak.) No finding.**

**S4 (Low). Deploy script `scripts/deploy.sh` uses `sudo rsync` over SSH to oracle-new
with `StrictHostKeyChecking=yes` and a pinned known_hosts — good — but the smoke test
runs `SSH "head -1 /var/www/gray/install.sh"` which is fine. No finding.**

**S5 (Note). Registry has no rate limit on `GET /api/plugins/index.json`; fine for its
scale but a cache/CDN-less origin can be squeezed. Consider the same limiter or nginx
limiting.**

## grayplugins

### gray-discord-plugin (the agent-carrying Discord surface, 21.7k lines)

**Verified solid:** owner/allowlist admission is checked centrally in `policy::incoming`
and `slash_admission` (owner or `allowed_users` only; bots and empty owners dropped;
guild messages require the @(bot) mention, which is stripped). DM pairing is one-shot,
single-use, 300-second codes. Outbound sends always set `allowed_mentions: parse:[]` —
the agent cannot ping random users. Attachment ingest caps 25 MiB/file, 100 MiB
conversation, no decoding (writes as files and hands paths to gray). Component media
`import_generated` canonicalizes and refuses paths outside the conversation root; URLs
are SSRF-gated (`blocked_host` + `resolved_host_is_blocked`) before fetch.

**D1 (Medium). `policy::incoming` trusts the `owner` string defensively but not
authoritatively.** `is_allowed_user(author, owner, allowed)` does an equality check on
the owner id — if config ever parses the owner from an editable source (state.json
`owner_id`), the first DM pairing becomes owner. That is documented as intended
("the first approval becomes owner"), but note: a random person DMing an unconfigured
bot mints a pairing code; if the operator runs `gray discord pairing approve` without
checking who sent the code (8 alphanumerics — the prompt text says "their own Discord
ID" but the code itself is shown to them, so they can social-engineer approval), they
become owner. Recommend showing the requesting user's ID in the approve flow and
requiring a `--as <user_id>` confirm.

**D2 (Low). Attachment identity.** `component_input::collect_attachments` reads ids
from the raw payload; if ever wired to fetch-by-id without re-checking provenance,
that's a path. Currently fine.

### gray-telegram / gray-slack

Both prompt-sidecar plugins, no inbox. Slack reads `team_id` from the state — one-line
defense against cross-workspace message injection. Telegram long-polls `getUpdates`
with `allowed_updates:["message"]` + offset persistence. Prompt contexts tell the
model "never send secrets." No inbound-command parsing → injection risk lies entirely
in what gray chooses to run, which is the H2 problem above, not plugin-local.

### gray-ssh

`ssh_run`/`ssh_copy` with BatchMode, 32KB output cap, optional host allowlist from
`~/.gray/ssh/hosts`. The allowlist is the *only* thing standing between the model and
every SSH host in `~/.ssh/config`; when the file doesn't exist, all hosts are allowed
(unrestrictive default). Recommend flipping to deny-by-default once allowlisted.

### gray-credpool

**Verified solid:** the per-turn relay binds `127.0.0.1:0` (random local port), mints
a one-time bearer per turn, maps bearer→pool in an in-flight map, and 404s anything
unmatched. Request parser caps head/body sizes.

**C1 (Medium). Bearer path runs the whole turn upstream even though `auth` is checked
before bearer lookup? (Read again: it does compare `req.auth != "Bearer {bearer}"`
before pool lookup — so it IS gated; the comparison is on the raw Authorization
header rather than a timing-safe compare — a same-user attacker can't guess the bearer
faster than parsing, but this is a host-local single-user loopback socket so the
exposure is negligible. Downgraded to a note.)**

### gray-sandbox

bwrap-based, tool/before modify-fails-closed except when bwrap is missing (fails OPEN
with a one-time notification, documented). Config knobs, deny-read of credential dirs.
**Note:** `~/.ssh` is *deliberately* not denied, and `bash -lc '<quoted command>'`
means a `-c` command string is interpolated into an sh -c argument via bwrap. Quoting
review strongly recommended before any Sandbox escape audit. Mark as separate
follow-up, not a finding.

### gray-guard / gray-permissions

Single-file stub plugins (`main.rs`), reviewed for anything surprising — nothing
interesting; they are permission shapes for a gate the host doesn't enforce (see
SECURITY.md: "there is no approval prompt").

## graydiscordbot (support bot, moderation/leveling — not an agent surface)

DISCORD_TOKEN env var, guild ID config, starboard/steal with `Manage Expressions`
permission checks, no signature-verification surface (gateway bot, not webhook). No
agent-level privileges beyond the moderation it ships. No findings beyond noting it
has `node_modules` checked in (`npm i` artifacts in the repo, harmless).

## Priority fix list

1. H1 — argv off the gateway socket payloads (smallest diff, real leak).
2. H2 — project-level `.claude/commands`/AGENTS.md trust gate.
3. H3 — sign the update tarball chain (remove the single-origin RCE class).
4. D1 — confirm-before-approve in the Discord pairing flow.
5. S1 — stop trusting client-reported `cost_usd` in the credits ledger path.
6. S2 — `execFile` for the scp index sync.

# Gray-core deep red team — 2026-10-10 (second pass)

Every `gray-core` module read: agent_loop, agent_tools, agent_compact, parallel,
redaction, tool_out, spill, cache_warm, compact, squeeze, credential, input,
error, paths. Suite evidence: `cargo test -p gray-core` — 222 tests pass, exit 0.
Static review; findings below are code-read confirmed, not dynamically exploited.

## High

**GC-1. SpecialStrip hold + leaked-markup nudge = cheap turn amplification.**
`agent_loop.rs` (SpecialStrip, `leaked_call_markup`, MAX_LEAK_NUDGES=3). The strip
set is fixed and emitted verbatim in this file's constants; tool output or a site
that prompts the model to print two of the specials in a reply burns up to 3 extra
rounds per leak event (each round replays the full prompt). Also: a trailing `<`
m_buffers until flush; prose containing the specials inside fenced code is
swallowed from the stream and history. Bounded (3 nudges) but a real cost lever.

**GC-2. Redactor token-unwrapping misses backtick/asterisk-wrapped secrets.**
`redaction.rs`. `redact_token`'s SECRET_VALUE_PREFIXES check runs on the raw token;
`unwrap_token` strips `(["'<>` but not backticks or `*`, and `trim_path_punctuation`
( which DOES strip backticks) is only consulted by `classify_path`. So
`` key=`sk-live-abc123def456` `` survives with the secret intact and a receipt
claiming nothing was removed. The same redactor fronts provider-wire summaries,
logs and durable receipts. One-line-class fix: strip backticks/asterisks in
`unwrap_token`; add a regression test next to
`secret_shaped_tokens_and_assignments_are_replaced`.

**GC-3. Cache-warm refresh replays the provider request with no scrub/redaction
gate.** `cache_warm.rs::keep_warm` streams the same ChatRequest at 90% TTL. Any
credential-shaped-but-unrecognized token in a tool result (16-char alpha+digit
values with no marker prefix: passwords, session ids, JWT fragments) rides a second,
silent provider call that produces no event, no receipt, no UI. Combined with GC-2
this is the actual leak path; a fix should route the warm request through the same
`scrubbed_messages` gate (it already clones `req`, so a scrub pass is cheap) or
gate on a post-scan.

## Medium

**GC-4. `tar` (and archive extractors) masquerade as `Touch::ReadsUnknown` and
batch with concurrent readers.** `parallel.rs`. `bash_is_batchable("tar xf a.tar")`
returns true (no MUTATOR word, no `>`, first verb not in READ_VERBS), and
`bash_touch` then classifies it via `bash_is_batchable(command).then_some
touch::ReadsUnknown)` — but extraction WRITES arbitrary files. `touches_interfere`
lets ReadsUnknown batch freely with Reads, so a concurrent `grep`/`read` executes
alongside an extract. Fix: add `tar`/`unzip`/`gunzip`/`bsdtar`/`7z`/`cpio` to the
demote list (one line + test).

**GC-5. Spill store is an unredacted, TTL-less second secret store.**
`tool_out.rs::finish` spills the RAW output (pre-redaction) to
`$GRAY_HOME/spill/<sha>.txt`; eviction is count-only (256), no TTL, and
`gray spill cat` serves it back verbatim. Deliberate per the module doc
("redaction happens on the way into the model's context, not on the way to disk"),
but on-disk secrets outlive any scrub and are invisible to anyone auditing
"does gray keep secrets". Recommend: TTL/purge on session close, or at minimum a
SECURITY.md line so operators know `/spill` holds raw output.

**GC-6. Parallel lane screening runs on the model-sent command, before any
`tool_before` rewrite.** `parallel.rs` docstring + `plan_segments`. A plugin hook
that rewrites `command` (gray-sandbox's modify-wrapping, bash-env preludes) makes
the batch decision from the pre-rewrite text; a rewrite that should demote a
call to the sequential path cannot. No current plugin does this, but the contract
is one hook away from wrongness — screening should run post-rewrite.

## Low

- **GC-7.** `error.rs::retryable()` includes `Stream`; hostile provider retryable
  streams burn MAX_TURN_RETRIES x provider budget silently across rounds. No
  global per-session retry budget across rounds.
- **GC-8.** `spill::store`/`record` best-effort mode enforcement is silent when
  chmod fails (no warning). Labeling only.
- **GC-9.** `compact.rs::tool_result_stub` embeds the raw session id in
  provider-visible stub text on every 8KiB+ elision. Mask to a hash.
- **GC-10.** `image_block_tokens` clamps at 4096; provider-reported usage remains
  authoritative, but budget estimate drift on multi-MB images is real.
- **GC-11.** `input.rs` forever accepts LEGACY protocol `gray.discord.input` —
  schedule a sunset.

## Verified-solid in gray-core

- Orphan-call repair on every cancel/abort/panic/shortfall path
  (`answer_pending_range` + synthetic backfill) — the strict-provider bricking
  class is dead here.
- Stream hardening: tool-call index cap 4096 before Vec growth, id/name
  immutability with protocol-error-on-conflict, 500k event cap, per-call timeout
  honored in both lanes.
- CCRM scrub (`contaminated` + `scrubbed_messages`): failed partials never
  re-ride a request; compaction consumes the scrubbed view.
- Compaction: clone-then-commit with strict-shrink gate, cheap no-gain bail,
  position-based anchor exclusion that never double-charges.
- Loop backstops: 6-identical-signature abort, 20-round poll cap correctly
  distinguishing job polls from stalls, bounded retries per round.
- `credential.rs`: Zeroizing-backed SecretString, redacted Debug, 128KiB cap.

gray-core priority order: GC-4 (one-line fix) → GC-2 (small fix + test) →
GC-3 (route warm request through the scrub) → GC-1 → GC-5/GC-6.
